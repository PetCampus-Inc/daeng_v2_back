# KD3-415 ADR 현행 기준 혼동 방지 문서 정비

| 항목 | 값 |
|---|---|
| Jira | `KD3-415` |
| 브랜치 | `docs/KD3-415-adr-current-source-of-truth` |
| 상위 에픽 | `KD3-403` |

## 현재 제어점

- 활성 workflow: `008-docs`
- 현재 공통 단계: `5`
- 다음 결정 또는 전환 조건: KD3-415 변경만 포함한 PR 범위와 독립 리뷰를 확인한다.

## 작업 목표

ADR이 과거 결정의 배경과 이력을 보존하는 기록이라는 점을 명확히 해, AI가 ADR과 현재 코드·최신 상태 문서의 차이만으로 결함이나 문서 갱신 필요성을 주장하지 않도록 한다.

## 작업 범위

- `docs/README.md`에서 ADR의 읽기 목적을 당시 결정의 배경·이력 확인으로 명시한다.
- ADR을 현재 사실·설계의 단일 출처처럼 표현한 `docs/service.md`와 `docs/inventory/api.md`를 수정한다.
- 기존 ADR을 이관 판단의 유일한 기준처럼 사용할 수 있는 `docs/workflows/003-migration.md` 표현을 수정한다.
- 문서 간 링크·표현·판정 기준을 상호 대조한다.
- `docs/` 전체를 검토해 ADR을 현행 제약 또는 현재 사실의 단일 기준처럼 표현하는 문서와, 작업 기록을 현재 규칙처럼 읽게 할 수 있는 표현을 식별한다.

## 작업 제외 범위

- 기존 ADR의 본문·결정·상태를 변경하거나 대체 ADR을 작성하지 않는다.
- 코드, API, 데이터베이스, 인프라 동작을 변경하지 않는다.
- ADR을 인용하는 모든 도메인·아키텍처 문서를 일괄 수정하지 않는다. 실제로 현행 규칙과 충돌하는 표현이 확인된 문서만 별도로 판단한다.
- `docs/README.md`의 기본 읽기 순서와 `docs/rules/documentation.md`의 역할을 분리·재설계하지 않는다. 이 구조 개편은 KD3-416에서 다룬다.

## 방향 논의 및 결정 사항

### 확정 사항

- 현재 사실과 구현의 기준은 코드와 최신 상태 문서(`domains/`, `architecture/`, `inventory/`, `conventions/`)이며, ADR은 당시 결정의 배경과 이력 확인용이다.
- ADR과 현재 기준의 차이만으로는 결함 또는 갱신 필요성을 판정하지 않는다.
- 최신 기준 문서가 특정 ADR을 현재도 유효한 제약으로 명시하고 그 제약과 불일치할 때만 리뷰 이슈로 제기한다.
- 이번 작업은 문서 운영·리뷰 판정 규칙의 명확화이므로, 되돌리기 어려운 시스템 결정에 해당하지 않아 새 ADR을 만들지 않는다.
- 상위 에픽은 `KD3-403`이다. 사용자의 명시적 지시에 따라 이 티켓 브랜치는 epic 브랜치를 거치지 않고 `dev`에서 생성해 `dev`로 직접 PR을 올린다.
- 문서 탐색 규칙과 문서 작성 규칙의 역할 분리는 KD3-416의 별도 설계·구현 범위다. KD3-415는 ADR을 현재 사실·설계의 단일 출처처럼 표현한 부분만 수정한다.

### 미결 질문

- `003-migration.md`에 최신 기준 우선 원칙을 명시할 필요가 있는지, `006-code-review.md`의 실제 ADR 대조 표현을 확인한 뒤 결정한다.
- `docs/domains/auth.md`처럼 과거 ADR을 “설계 근거”로 열거한 문서에 현행성 표기를 추가할 필요가 있는지, 변경 후 규칙과 실제 표현을 대조해 판단한다.

### 전수 검토 결과

- `docs/rules/documentation.md`는 ADR의 append-only 방식은 규정하지만, ADR과 현재 기준 문서가 다를 때의 우선순위와 리뷰 판정 조건은 규정하지 않는다. 이 책임 분리는 KD3-416에서 다룬다.
- `docs/README.md`는 ADR을 다른 현재 상태 문서와 같은 읽기 단계에 나열해, 배경 확인용이라는 구분이 없다. 읽기 목적과 우선순위를 보강해야 한다.
- `docs/service.md`는 Java→Kotlin 이관의 세부 판단 근거가 ADR의 “단일 출처”라고 명시한다. 현재 판단의 근거를 ADR에 귀속하므로 직접 수정 대상이다.
- `docs/workflows/003-migration.md`는 인벤토리와 기존 ADR로 이관 판정을 하도록만 적어, 최신 인벤토리·코드·실제 소비처의 우선성을 드러내지 않는다. 수정 대상이다.
- `docs/inventory/api.md`는 삭제·재설계·보류 근거가 있는 항목에서 기존 ADR 판정을 “우선 반영”한다고 적는다. 이 표현은 ADR을 현재 판정의 상위 기준으로 만들므로 수정 대상이다.
- `docs/conventions/api-contract.md`, `docs/architecture/hexagonal.md`, `docs/domains/auth.md`, `docs/inventory/database.md`, `docs/inventory/operations.md`의 ADR 링크는 현재 규칙·사실을 해당 문서 본문에 두고 배경·근거로 ADR을 참조한다. 링크의 목적만 명확히 하면 되며, 현재 단계에서 일괄 수정 대상은 아니다.
- `docs/adr/` 10건과 기존 `docs/work/` 기록은 역사 기록이다. 특히 ADR `0009`는 현재 폴더 용도의 기준이 `README.md`와 `documentation.md`라고 명시한다. append-only 원칙에 따라 기존 ADR·완료 작업 기록은 수정하지 않는다.
- 나머지 `rules/`, `conventions/`, `domains/`, `inventory/`, `workflows/` 문서에서는 ADR을 현행 기준보다 우선하는 표현을 발견하지 못했다.
- `node scripts/docs-check.mjs`는 문서 40개 기준으로 통과했다.
