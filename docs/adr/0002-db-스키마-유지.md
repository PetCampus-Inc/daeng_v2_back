# 0002. DB는 기존 운영 스키마 그대로 사용

## 맥락

Java → Kotlin 마이그레이션과 동시에, 오래돼 어색해진 테이블 스키마를 재설계할지 결정이 필요했다.

## 검토한 후보

1. 마이그레이션과 함께 스키마도 재설계한다.
2. 기존 운영 스키마를 그대로 두고, 언어/아키텍처 전환만 이번 스프린트 범위로 한정한다.

## 결정

**후보 2 — 기존 운영 스키마를 이번 스프린트에서 재설계하지 않는다.**

근거: 언어/아키텍처 변경과 스키마 변경을 동시에 하지 않는다. 같은 DB를 그대로 쓰면 컷오버 롤백이 LB(로드밸런서) 전환만으로 무료가 된다 — 실패 시 되돌릴 대상이 코드뿐이다.

## 결과

- 신규(Kotlin) 서버는 기존 MySQL/Redis 스키마를 그대로 읽고 쓴다.
- 스키마 재설계는 후속 스프린트로 미룬다. 컷오버 전략은 [`0008-무중단-컷오버-전략.md`](0008-무중단-컷오버-전략.md) 참고.
