# 0001. 레거시(v1/v2) 블록 전면 삭제

## 맥락

레거시 자바 서버(`knockdog_server`, `daeng_v1_back`)는 v1 → v2 → v3로 넘어오며 아키텍처·API 컨벤션·인증 흐름이 혼재됐다. `daeng_v2_back`(Kotlin)으로 마이그레이션하면서 이 레거시 블록을 신규 서버로 그대로 가져갈지 결정해야 했다.

## 검토한 후보

1. 레거시 컨트롤러/서비스를 신규 서버에도 그대로 포팅해 하위 호환을 유지한다.
2. 레거시 블록을 신규 서버로 가져가지 않고 폐기한다.

## 결정

**후보 2 — 레거시(v1/v2) 블록 전면 삭제.** 신규 서버로 가져가지 않는다.

근거:
- 레거시 컨트롤러는 전부 `@Deprecated` 상태이고 마지막 실질 변경이 2025-08이다.
- 실제 배포 중인 `daeng_v1_mobile`(살아있는 앱, v0.5.9)이 `daeng_v2_front`만 로드하는 것을 확인했다 — 레거시 API 소비자가 없다.

## 결과

신규 서버는 `daeng_v2_front`가 실제로 호출하는 v0/v1 API만 구현 대상으로 삼는다. 판정 기준과 전체 API 인벤토리는 [`0004-api-v0-유지-v1-신규.md`](0004-api-v0-유지-v1-신규.md)를 참고한다.
