# 설계·조사 작업 추가 절차

이 문서는 [`000-common.md`](000-common.md)의 공통 단계에 결합하는 추가 조건이다. 별도의 단계·작업 문서 양식을 만들지 않는다. 설계·조사의 질문, 근거, 권고안, 검증 결과는 `docs/work/<JIRA-KEY>-<slug>.md`에 기록한다. 조사 결과, 확인된 사실, 가정, 권고안을 구분하며, 사용자 승인 전에는 설계 결정을 구현으로 간주하지 않는다.

## 1단계에 추가할 확인 사항

- 해결할 문제, 결정권자, 필요한 산출물과 결정 기한을 확인한다.
- 기능·비기능 요구사항, 기존 계약, 보안·운영·비용·일정 제약을 확인한다.
- 근거가 없는 전제는 가정으로 표시하고, 확인이 필요한 질문을 사용자에게 제시한다.
- **기록:** 해결할 질문과 산출물은 `작업 목표`에, 조사 대상·제약·가정은 `작업 범위`와 `방향 논의 및 결정 사항`에 남긴다.

## 2단계에 추가할 계획·승인 조건

- 구현 가능한 대안과 평가 기준(유지보수성, 정합성, 보안, 성능, 운영성, 비용)을 정한다.
- 장기 영향 또는 여러 도메인에 영향을 주는 선택은 ADR 필요 여부를 판단한다.
- 사용자 승인은 조사 범위, 평가 기준, 권고안의 검증 계획을 포함해야 한다.
- **기록:** 평가 기준, ADR 판단, 사용자 승인 기록은 `방향 논의 및 결정 사항`에 남긴다. 권고안의 완료 판단 기준은 `완료 확인 기준`에 남긴다.

## 3단계에 추가할 수행 조건

- 코드·문서·운영 정보와 신뢰할 수 있는 외부 근거를 확인한다. 출처와 관찰 사실을 분리한다.
- 대안별 장단점, 위험, 전제, 도입·rollback 방법을 비교하고 권고안을 제시한다.
- **기록:** 확인된 사실·가정, 대안 비교, 권고안과 근거는 `방향 논의 및 결정 사항`에 남긴다.

## 4단계에 추가할 검증 조건

- 권고안이 해결하려는 요구사항과 제약을 만족하는지 검토한다.
- 근거가 부족하거나 검증하지 못한 영향은 제한으로 명시한다.
- **기록:** 요구사항·제약 충족 여부, 추가 검증과 제한은 `완료 확인 기준`에 남긴다.

## 5단계에 추가할 검토·문서화 조건

- 리뷰어는 질문·제약, 대안 근거, 권고안과 제한이 작업 문서 및 조사 근거와 일치하는지 대조한다.
- 확정된 사실과 결정은 `documentation.md`의 배치·갱신 기준에 따라 해당 문서에, 미확정 논의는 `work/` 문서에 남긴다.
- 권고안 구현은 별도 Jira 작업으로 분리한다.
