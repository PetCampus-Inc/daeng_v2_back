# 설계·조사 작업 절차

설계·조사는 [`000-common.md`](000-common.md)의 작업 유형 적용 표에 따라 수행한다. 조사 결과, 확인된 사실, 가정, 권고안을 구분하며, 사용자 승인 전에는 설계 결정을 구현으로 간주하지 않는다.

## 대화 단계와 게이트

| 단계 | 다음 단계로 넘어갈 조건 |
|---|---|
| D1 질문·제약 확인 | 해결할 질문, 산출물, 제약과 미확인 가정이 구분됨 |
| D2 대안·권고안 작성 | 대안별 근거·위험·운영 영향과 권고안이 정리됨 |
| D3 결정 또는 구현 작업 전환 | 사용자가 권고안을 승인하거나, 별도 Jira 구현 작업으로 분리함 |

## 1. 질문과 제약 확인

- 해결할 문제, 결정권자, 필요한 산출물과 결정 기한을 확인한다.
- 기능·비기능 요구사항, 기존 계약, 보안·운영·비용·일정 제약을 확인한다.
- 근거가 없는 전제는 가정으로 표시하고, 확인이 필요한 질문을 사람에게 제시한다.

## 2. 대안과 평가 기준 결정

- 구현 가능한 대안과 평가 기준(유지보수성, 정합성, 보안, 성능, 운영성, 비용)을 정한다.
- 장기 영향 또는 여러 도메인에 영향을 주는 선택은 ADR 필요 여부를 판단한다.

## 3. 조사와 설계

- 코드·문서·운영 정보와 신뢰할 수 있는 외부 근거를 확인한다. 출처와 관찰 사실을 분리한다.
- 대안별 장단점, 위험, 전제, 도입·rollback 방법을 비교하고 권고안을 제시한다.

## 4. 검증과 문서화

- 권고안이 해결하려는 요구사항과 제약을 만족하는지 검토한다.
- 확정된 결정은 ADR 또는 관련 아키텍처·도메인 문서에, 미확정 논의는 `work/` 문서에 남긴다.

## 5. 작업 문서 필수 반영 항목

- 문제·제약·확인된 사실과 미확정 가정
- 검토한 대안과 평가 기준, 권고안과 근거
- 위험, 비용·운영 영향, 후속 검증 또는 결정 사항
