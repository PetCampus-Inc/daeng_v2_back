# 코드 리뷰 작업 절차

코드 리뷰는 [`000-common.md`](000-common.md)의 작업 유형 적용 표에 따라 수행한다. 기본값은 읽기 전용이며, 수정은 리뷰 대상자가 명시적으로 요청하거나 별도 수정 작업으로 전환한 경우에만 한다.

## 대화 단계와 게이트

| 단계 | 다음 단계로 넘어갈 조건 |
|---|---|
| R1 리뷰 범위·기준 확인 | base/head 또는 PR, 관련 작업 문서, 중점 검토 항목이 확인됨 |
| R2 근거 기반 리뷰 | 발견 사항이 코드 경로·실패 시나리오·심각도와 함께 정리됨 |
| R3 결과·후속 작업 확인 | 검증 한계와 수정이 필요한 항목이 구분되고, 수정은 별도 작업으로 전환됨 |

## 1. 리뷰 범위와 기준 확인

- base/head 커밋 또는 PR, 관련 작업 문서, 변경 목적과 제외 범위를 확인한다.
- 보안, 데이터 정합성, 계약 호환성, 성능, 운영 안정성 중 중점 검토 항목을 확인한다.
- 범위나 요구사항을 확인할 수 없으면 추측으로 결함을 단정하지 않고 제한 사항으로 남긴다.

## 2. 리뷰 방향 결정

- 각 발견 사항은 실제 코드 경로와 실패 시나리오를 근거로 심각도를 판단한다.
- 스타일 선호와 배포·사용자 영향이 있는 문제를 구분한다.
- 리뷰만으로 검증할 수 없는 항목은 필요한 테스트·운영 확인을 제안하되 통과한 것처럼 표현하지 않는다.

## 3. 리뷰 수행

- 작업 문서와 diff를 대조해 누락, 범위 초과, 계약·동시성·오류 처리·권한·rollback 위험을 확인한다.
- 발견 사항은 심각도 순으로 파일·위치·근거·영향·개선 방향을 남긴다.
- 이슈가 없으면 검토 범위와 검증하지 못한 영역을 명시한다.

## 4. 검증과 문서화

- 가능하면 관련 테스트, 정적 분석, diff를 읽기 전용으로 검증한다.
- 후속 수정이 필요하면 별도 작업으로 추적하고, 리뷰 자체는 코드 변경 없이 종료할 수 있다.

## 5. 작업 문서 필수 반영 항목

- 리뷰 대상 범위·요구사항·검토 중점
- 심각도별 발견 사항과 재현 또는 코드 근거
- 검증한 항목과 검증하지 못한 제한
- 후속 수정 또는 승인 판단
