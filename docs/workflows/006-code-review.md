# 코드 리뷰 작업 추가 절차

이 문서는 [`000-common.md`](000-common.md)의 공통 단계에 결합하는 추가 조건이다. 별도의 단계·작업 문서 양식을 만들지 않는다. 코드 리뷰의 범위·발견 사항·검증 결과는 `docs/work/<JIRA-KEY>-<slug>.md`에 기록한다. 기본값은 읽기 전용이며, 수정은 리뷰 대상자가 명시적으로 요청하거나 별도 수정 작업으로 전환한 경우에만 한다.

## 1단계에 추가할 확인 사항

- base/head 커밋 또는 PR, 관련 작업 문서, 변경 목적과 제외 범위를 확인한다.
- 보안, 데이터 정합성, 계약 호환성, 성능, 운영 안정성 중 중점 검토 항목을 확인한다.
- 범위나 요구사항을 확인할 수 없으면 추측으로 결함을 단정하지 않고 제한 사항으로 남긴다.
- **기록:** 리뷰 대상과 중점 검토 항목은 `작업 목표`와 `작업 범위`에, 검토하지 않는 영역과 제한은 `작업 제외 범위`에 남긴다.

## 2단계에 추가할 계획·승인 조건

- 각 발견 사항은 실제 코드 경로와 실패 시나리오를 근거로 심각도를 판단한다.
- 스타일 선호와 배포·사용자 영향이 있는 문제를 구분한다.
- 리뷰만으로 검증할 수 없는 항목은 필요한 테스트·운영 확인을 제안하되 통과한 것처럼 표현하지 않는다.
- 사용자 승인은 리뷰 범위와 중점 검토 항목을 포함해야 한다.
- **기록:** 심각도 기준, 요구사항 해석, 검증 한계와 승인 기록은 `방향 논의 및 결정 사항`에 남긴다. 리뷰 완료 판단 기준은 `완료 확인 기준`에 남긴다.

## 3단계에 추가할 수행 조건

- 작업 문서와 diff를 대조해 누락, 범위 초과, 계약·동시성·오류 처리·권한·rollback 위험을 확인한다.
- 발견 사항은 심각도 순으로 파일·위치·근거·영향·개선 방향을 남긴다.
- 이슈가 없으면 검토 범위와 검증하지 못한 영역을 명시한다.
- 코드 수정은 하지 않는다. 수정이 필요하면 별도 작업으로 전환한다.
- **기록:** 발견 사항과 근거, 영향, 개선 방향은 `방향 논의 및 결정 사항`에 남긴다.

## 4단계에 추가할 검증 조건

- 가능하면 관련 테스트, 정적 분석, diff를 읽기 전용으로 검증한다.
- 검증하지 못한 항목은 이유와 제한을 명시한다.
- **기록:** 읽은 diff, 실행한 검증, 검증하지 못한 제한은 `완료 확인 기준`에 남긴다.

## 5단계에 추가할 검토·문서화 조건

- 이 workflow는 리뷰 결과 자체에 대한 추가 독립 리뷰를 요구하지 않는다. 사용자가 요청하거나 고위험 변경의 머지 게이트인 경우에만 별도 독립 리뷰를 수행한다.
- 후속 수정이 필요하면 별도 작업으로 추적하고, 리뷰 자체는 코드 변경 없이 종료할 수 있다.
