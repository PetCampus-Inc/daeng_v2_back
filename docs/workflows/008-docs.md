# 문서화 작업 추가 절차

이 문서는 [`000-common.md`](000-common.md)의 공통 단계에 결합하는 추가 조건이다. 별도의 단계·작업 문서 양식을 만들지 않는다. 문서화의 범위·근거·검증 결과는 `docs/work/<JIRA-KEY>-<slug>.md`에 기록한다. 문서의 목적은 사실을 장기적으로 전달하는 것이므로, 추측이나 미검증 상태를 확정 사실처럼 기록하지 않는다.

## 1단계에 추가할 확인 사항

- 독자, 해결할 질문, 최신 상태를 유지할 책임 범위를 확인한다.
- [`docs/rules/documentation.md`](../rules/documentation.md)의 배치·갱신 기준으로 문서 위치와 기존 단일 기준 문서를 확인한다.
- 코드, 테스트, 운영 설정, 승인된 결정 등 사실 근거를 확인하고, 미확정 내용은 별도 표시한다.
- **기록:** 대상 독자와 문서 목적은 `작업 목표`에, 문서 위치·기존 단일 기준 문서·사실 근거는 `작업 범위`에 남긴다.

## 2단계에 추가할 계획·승인 조건

- 기존 문서를 갱신할지 새 문서를 만들지와 중복을 제거할 기준 문서를 결정한다.
- 기술 결정이나 규칙을 새로 도입하는 경우 문서화 전에 ADR 또는 사용자 승인이 필요한지 판단한다.
- 사용자 승인은 생성·수정·삭제 범위와 중복 제거 판단을 포함해야 한다.
- **기록:** 생성·수정·삭제 범위, 중복 제거 판단, ADR 필요 여부와 승인 기록은 `방향 논의 및 결정 사항`에 남긴다. 사실 대조의 통과 기준은 `완료 확인 기준`에 남긴다.

## 3단계에 추가할 작성 조건

- 독자가 필요한 결론, 범위, 제약, 사용·검증 방법을 우선하여 작성한다.
- 실제 코드와 불일치하는 예시, secret, 확인되지 않은 운영값을 포함하지 않는다.
- **기록:** 작성 중 범위·사실 근거·기준 문서가 바뀌면 `작업 범위` 또는 `방향 논의 및 결정 사항`을 먼저 갱신한다.

## 4단계에 추가할 검증 조건

- 링크, 경로, 명령어, 수치, 코드 예시를 원본과 대조한다.
- 관련 문서와의 중복·모순을 확인한다.
- **기록:** 검증한 링크·경로·명령어와 확인하지 못한 제한은 `완료 확인 기준`에 남긴다.

## 5단계에 추가할 검토·문서화 조건

- 리뷰어는 문서의 목적·범위·사실 근거·검증 결과가 실제 변경과 일치하는지 대조한다.
- 바뀐 사실에 영향받는 문서는 `documentation.md`의 배치·갱신 기준에 따라 함께 갱신한다.
