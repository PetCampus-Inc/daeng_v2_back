# 문서화 작업 절차

문서화는 [`000-common.md`](000-common.md)의 작업 유형 적용 표에 따라 수행한다. 문서의 목적은 사실을 장기적으로 전달하는 것이므로, 추측이나 미검증 상태를 확정 사실처럼 기록하지 않는다.

## 대화 단계와 게이트

| 단계 | 다음 단계로 넘어갈 조건 |
|---|---|
| W1 목적·근거·정식 위치 확인 | 독자, 문서 목적, 사실 근거와 기존 단일 기준 문서가 확인됨 |
| W2 작성 범위 승인 | 생성·수정·삭제 범위와 중복 제거 판단을 사용자가 확인함 |
| W3 사실 대조·완료 판단 | 링크·경로·명령어·코드 예시와 관련 문서의 정합성이 확인됨 |

## 1. 문서 목적과 정식 위치 확인

- 독자, 해결할 질문, 최신 상태를 유지할 책임 범위를 확인한다.
- [`docs/rules/documentation.md`](../rules/documentation.md)의 배치 규칙으로 문서 위치와 기존 단일 기준 문서를 확인한다.
- 코드, 테스트, 운영 설정, 승인된 결정 등 사실 근거를 확인하고, 미확정 내용은 별도 표시한다.

## 2. 작성 방향 결정

- 기존 문서를 갱신할지 새 문서를 만들지와 중복을 제거할 기준 문서를 결정한다.
- 기술 결정이나 규칙을 새로 도입하는 경우 문서화 전에 ADR 또는 사람의 승인이 필요한지 판단한다.

## 3. 작성

- 독자가 필요한 결론, 범위, 제약, 사용·검증 방법을 우선하여 작성한다.
- 실제 코드와 불일치하는 예시, secret, 확인되지 않은 운영값을 포함하지 않는다.

## 4. 검증과 문서화

- 링크, 경로, 명령어, 수치, 코드 예시를 원본과 대조한다.
- 관련 문서와의 중복·모순을 확인하고, 바뀐 사실에 영향받는 인벤토리·도메인 문서를 함께 갱신한다.

## 5. 작업 문서 필수 반영 항목

- 대상 독자, 목적, 정식 위치와 사실 근거
- 생성·수정·삭제 범위 및 중복 제거 판단
- 검증한 링크·경로·명령어와 확인하지 못한 제한
