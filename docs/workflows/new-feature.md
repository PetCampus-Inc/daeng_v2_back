# 신규 기능 작업 절차

모든 신규 기능 작업은 [`common.md`](common.md)의 **작업 유형 적용** 표에 따라 이 절차를 결합해 따른다. 이 파일은 공통 절차가 끝난 뒤 별도로 수행하는 순차 절차가 아니다. 2~3단계의 분석 결과는 티켓 본문에 기록하고, 5단계에서 `docs/work/<JIRA-KEY>-<slug>.md`로 옮긴 뒤 이후 결정·구현·검증 결과를 계속 갱신한다.

5단계에서는 아래 **작업 문서 양식**을 `docs/work/<JIRA-KEY>-<slug>.md`로 복사해 사용한다. 이 파일의 절차와 양식이 신규 기능 작업의 단일 기준이다.

## 1. 요구사항과 영향 범위 확인

- 사람과 대화해 사용자 가치, 완료 조건, 제외 범위를 확정한다. 모호한 요구사항은 구현으로 추정하지 않는다.
- 호출 주체, 권한, 기존 API·도메인·데이터와의 관계를 확인한다.
- 기존 계약을 바꾸는지 판단하고, 바뀐다면 버전 정책과 클라이언트 영향 범위를 확인한다.

## 2. 구현 방향 결정

- 대안이 있으면 유지보수성, 보안, 성능, 운영 영향 관점에서 비교하고 선택 이유를 작업 문서에 기록한다.
- 데이터 모델, 권한 경계, 오류 응답, 외부 연동, 관찰성 중 해당 항목의 설계를 구현 전에 결정한다.
- 여러 도메인이나 되돌리기 어려운 결정에 영향을 주면 ADR 필요 여부를 판단한다.

## 3. 구현

- 확정한 범위 안에서 구현한다. 구현 중 범위나 결정이 바뀌면 코드를 바꾸기 전에 작업 문서를 갱신하고 필요한 경우 사람과 다시 논의한다.
- API를 추가·변경하면 API 계약과 Notion 명세 동기화 대상 여부를 확인한다.

## 4. 검증과 문서화

- 단위·통합·경계 테스트 등 변경 위험에 맞는 자동 검증을 실행하고 결과를 확인한다.
- 인가, 입력 검증, 오류 경로, 기존 기능 회귀를 포함해 완료 기준을 검증한다.
- 구현 결과에 따라 도메인, API, 데이터베이스, 아키텍처, ADR, 운영 문서의 갱신 필요 여부를 확인한다.

## 5. 작업 문서 필수 반영 항목

- 사용자 관점의 작업 목표와 완료 조건
- 생성·수정·삭제 범위 및 명시적인 제외 범위
- 검토한 대안, 결정 이유, 계약·보안·데이터 영향
- 실행한 검증과 결과, 갱신한 문서 목록
