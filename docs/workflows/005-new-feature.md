# 신규 기능 작업 추가 절차

이 문서는 [`000-common.md`](000-common.md)의 공통 단계에 결합하는 추가 조건이다. 별도의 단계·작업 문서 양식을 만들지 않는다. 신규 기능의 상세 요구사항·결정·검증 결과는 `docs/work/<JIRA-KEY>-<slug>.md`에 기록하고 Jira 본문에는 복제하지 않는다.

## 1단계에 추가할 확인 사항

- 사용자 가치, 사용자·호출 주체, 완료 조건, 제외 범위를 확인한다. 모호한 요구사항을 구현으로 추정하지 않는다.
- 권한 경계와 기존 API·도메인·데이터·외부 연동과의 관계를 확인한다.
- 기존 계약 변경 여부와, 변경 시 버전 정책·기존 클라이언트 영향 범위를 확인한다.
- **기록:** 확인 결과를 작업 문서의 `작업 목표`, `작업 범위`, `작업 제외 범위`에 남긴다.

## 2단계에 추가할 계획·승인 조건

- 대안이 있으면 유지보수성, 보안, 성능, 운영 영향으로 비교하고 선택 이유를 기록한다.
- 데이터 모델, 권한 경계, 오류 응답, 외부 연동, 관찰성 중 해당 항목의 설계를 구현 전에 결정한다.
- 여러 도메인에 영향을 주거나 되돌리기 어려운 결정이면 ADR 필요 여부를 판단한다.
- 사용자 승인은 구현 범위, 주요 설계 결정, 검증 계획을 포함해야 한다.
- **기록:** 대안·선택 이유, 계약·보안·성능·운영 영향, ADR 판단과 승인 기록은 `방향 논의 및 결정 사항`에 남긴다. 검증 방법과 통과 기준은 `완료 확인 기준`에 남긴다.

## 3단계에 추가할 구현 조건

- 확정한 범위 안에서 구현한다. API를 추가·변경하면 API 계약과 Notion 명세 동기화 대상 여부를 확인한다.
- 구현 중 요구사항·권한·계약·운영 영향이 바뀌면 작업 문서를 먼저 갱신하고 필요한 경우 1단계 또는 2단계로 돌아간다.
- **기록:** 구현 중 범위나 설계가 바뀌면 `작업 범위` 또는 `방향 논의 및 결정 사항`을 먼저 갱신한다.

## 4단계에 추가할 검증 조건

- 단위·통합·경계 테스트 등 변경 위험에 맞는 자동 검증을 실행한다.
- 인가, 입력 검증, 오류 경로, 기존 기능 회귀, 계약 호환성을 완료 기준과 대조한다.
- **기록:** 검증 방법, 통과 기준, 실제 결과와 제한은 `완료 확인 기준`에 남긴다.

## 5단계에 추가할 검토·문서화 조건

- 리뷰어는 사용자 가치, 완료 기준, 권한·계약 영향, 명시적 제외 범위를 작업 문서와 diff에 대조한다.
